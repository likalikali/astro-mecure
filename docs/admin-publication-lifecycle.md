# 后台发布生命周期

线上发布状态、后台暂存版本、当前编辑是否保存，是三个不同维度。

| 当前内容 | 暂存 | 发布 | 撤回 |
| --- | --- | --- | --- |
| 新文章 | 保存为仅管理员可见的草稿 | 填写标题正文后首次发布 | 不显示 |
| 未发布草稿 | 更新草稿 | 首次发布，首次上传时间留空时记录当前时间 | 不显示 |
| 已发布文章 | 保存独立工作副本，线上保持原版 | 替换线上内容，保留首次上传时间 | 下线并保留内容为草稿 |
| 已发布且有暂存修改 | 更新工作副本 | 发布暂存或当前编辑内容 | 下线，最新暂存内容保留为草稿 |
| 关于等独立页面 | 保存工作副本，不改变线上页面 | 更新线上页面 | 不允许撤回或删除固定页面 |

- 删除文章后显示“已删除”，不显示“发布成功”。删除采用原有软删除和版本记录。
- 成功反馈仅属于刚才的操作。重新编辑、打开其他内容、新建文章或开始另一项操作，立即清除。
- 修改后的文字与载入时一致时，恢复已保存状态，不制造无意义更新。
- 暂存和发布进行中，锁定编辑区及切换入口，防止重复操作或成功响应覆盖刚输入的文字。
- 未保存时切换、新建、退出或重新载入均提醒。已暂存但尚未发布可直接离开。
- 保存失败保留输入。版本冲突提供复制正文与重新载入；登录过期保留整个编辑器，重新登录后由用户重新提交。
- 尚未保存的修改存在时，不允许撤回或放弃暂存，避免状态操作隐含丢失当前输入。
- 首次上传时间只在首次发布时自动记录；暂存已发布文章不会改变线上任何时间。用户未编辑的时间精确值（含毫秒）保留。

实现：`blog_documents.source/meta/html` 为已发布版本（未发布文章则是草稿）；`working_source` 保存已发布内容的私有工作副本。所有写操作使用统一版本号做原子冲突检查，版本触发器继续保留历史。

验证覆盖：新建→暂存→首次发布→编辑→暂存但线上不变→重新打开→发布更新→放弃暂存→撤回→重新发布→删除；网络失败、401、409、重复点击、加载期间切换、空内容、修改后恢复原文、移动布局。
